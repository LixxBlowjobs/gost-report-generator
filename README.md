# GOST Report Generator

Генератор отчётов о НИР по **ГОСТ 7.32-2017**. Анализирует исходный код проекта через бесплатные LLM (OpenRouter) и собирает готовый DOCX-отчёт со всеми обязательными разделами.

## Что делает

На вход — путь к репозиторию. На выходе — `report.docx`:

- титульный лист, реферат, оглавление (Word TOC, обновляется по F9)
- термины, сокращения
- введение с цитированием источников
- 3 главы с подразделами, таблицами, рисунками и листингами
- заключение, список литературы (ГОСТ 7.1)

Текст проходит постобработку: убираются AI-штампы (delve, robust, comprehensive, «стоит отметить» и т. п.).

## Установка

Python 3.10+.

```bash
git clone https://github.com/LixxBlowjobs/gost-report-generator.git
cd gost-report-generator
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Или без editable-установки: `pip install -r requirements.txt`.

API-ключ OpenRouter — в `.env` в корне:

```
OPENROUTER_API_KEY=sk-or-v1-...
```

Получить бесплатно: https://openrouter.ai/keys

## Использование

### TUI (по умолчанию)

```bash
docgen
```

Полноэкранный интерфейс в терминале (Textual). Поддерживает `/`-команды:
`/project`, `/output`, `/generate`, `/check-models`, `/skip-llm`, `/analyze-only`, `/no-postprocess`, `/help`, `/quit`.

### CLI с дашбордом

```bash
docgen -p /path/to/project -o report.docx
```

### CLI простой режим

```bash
docgen -p /path/to/project --simple
```

### С метаданными

```bash
docgen -p /path/to/project -m meta.json
```

`meta.json`:
```json
{
  "topic": "Тема исследования",
  "student_name": "Иванов И. И.",
  "group": "ИВТ-41",
  "supervisor": "Петров П. П.",
  "university": "Название университета",
  "year": 2026
}
```

### Опции

| Флаг | Что делает |
|------|------------|
| `-p`, `--project` | Путь к проекту |
| `-o`, `--output` | Куда сохранить DOCX (по умолч. `report.docx`) |
| `-m`, `--metadata` | JSON с метаданными |
| `-a`, `--analysis` | Готовый JSON анализа (пропустить LLM) |
| `--save-analysis` | Сохранить результаты анализа в JSON |
| `--skip-llm` | Только сканирование, без LLM |
| `--analyze-only` | Только анализ, без генерации DOCX |
| `--no-postprocess` | Отключить постобработку текста |
| `--simple` | Простой вывод без live-панели |
| `--check-models` | Проверить доступность моделей |
| `--api-key` | Передать ключ OpenRouter явно |

## Как работает

1. **Сканирование** — обход файловой системы, сбор дерева, конфигов и содержимого основных файлов.
2. **LLM-анализ** — структурированный JSON: назначение, стек, архитектура, модули.
3. **План** — 3 главы по 2-4 подраздела, тезисы введения/заключения, темы литературы.
4. **Литература** — генерируется первой, чтобы главы могли ссылаться.
5. **Главы** — подразделы с абзацами, таблицами, рисунками, листингами.
6. **Постобработка** — чистка AI-штампов.
7. **Сборка** — DOCX с ГОСТ-форматированием: A4, поля 30/15/20/20 мм, Times New Roman 14pt, 1.5 интервал.

## Цепочка моделей

`llm.py` пробует по очереди, переходя к следующей при ошибке:

1. `google/gemini-2.5-flash`
2. `google/gemma-3-27b-it`
3. `google/gemini-2.5-flash-lite`

Генерация занимает 60-90 секунд на среднем проекте.

## Ограничения

- Литература генерируется LLM — проверяйте источники перед сдачей.
- Рисунки добавляются как подпись + описание. Изображения вставляйте вручную (или предоставьте PNG-файлы).
- Оглавление — Word TOC field, обновите через F9 после открытия.
