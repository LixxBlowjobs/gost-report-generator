# GOST Report Generator

Генератор отчётов о научно-исследовательской работе (НИР) по **ГОСТ 7.32-2017**. Анализирует исходный код проекта и автоматически собирает структурированный DOCX-отчёт через бесплатные LLM-модели OpenRouter.

## Что делает

На вход — путь к репозиторию. На выходе — `report.docx` со всеми разделами по ГОСТ:

- титульный лист
- реферат с ключевыми словами и сведениями об объёме
- оглавление (Word TOC field, обновляется по `F9`)
- термины и определения
- сокращения и обозначения
- введение с цитированием источников
- три главы: анализ предметной области, проектирование, реализация
- заключение
- список литературы (ГОСТ 7.1)

Каждая глава содержит подразделы с таблицами, рисунками-заглушками под скриншоты и листингами кода. После генерации текст прогоняется через постобработку, которая убирает типичные «AI-isms» (delve, robust, comprehensive, leverage, em-dash overuse, конструкции «не X — а Y», русские штампы вроде «стоит отметить» и пр.).

## Установка

Требования: Python 3.10+.

```bash
git clone <repo-url>
cd gost-report-generator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

API-ключ OpenRouter положите в `.env` в корне проекта:

```
OPENROUTER_API_KEY=sk-or-v1-...
```

Получить ключ можно бесплатно на https://openrouter.ai/keys.

## Использование

```bash
python -m src.docgen -p /path/to/project -o report.docx
```

С метаданными:

```bash
python -m src.docgen -p /path/to/project -o report.docx -m meta.json
```

Где `meta.json`:

```json
{
  "topic": "Тема исследования",
  "student_name": "Иванов И. И.",
  "group": "ИВТ-41",
  "supervisor": "Петров П. П.",
  "university": "Примерный университет",
  "year": 2026
}
```

### Опции CLI

| Флаг | Назначение |
|------|------------|
| `-p`, `--project` | Путь к анализируемому проекту (обязательно) |
| `-o`, `--output` | Куда сохранить DOCX (по умолч. `report.docx`) |
| `-m`, `--metadata` | JSON с метаданными отчёта |
| `-a`, `--analysis` | Готовый JSON анализа (пропустить LLM-анализ) |
| `--save-analysis` | Куда сохранить результаты анализа |
| `--skip-llm` | Только сканирование, без LLM (минимальный скелет) |
| `--analyze-only` | Только анализ проекта, без генерации DOCX |
| `--no-postprocess` | Отключить avoid-ai-writing постобработку |
| `--api-key` | Передать ключ OpenRouter явно |

## Как это работает

1. **Сканирование** — `analyzer/scanner.py` обходит файловую систему, фильтрует бинарники и каталоги типа `node_modules`, собирает дерево проекта, конфиги (`package.json`, `pyproject.toml`, `Dockerfile`, ...) и содержимое 30 крупнейших исходников.
2. **LLM-анализ** — `analyzer/llm_analyzer.py` отдаёт собранное модели и получает структурированный JSON: назначение проекта, стек, архитектура, ключевые модули и функции.
3. **План** — `sections/plan.py` строит 3 главы по 2-4 подраздела, тезисы введения и заключения, 10-15 тем для источников.
4. **Литература** — генерируется первой, чтобы главы могли ссылаться на источники.
5. **Главы** — каждая глава получает свой план, список источников и анализ. Подразделы заполняются абзацами с цитатами, таблицами, рисунками и листингами по флагам плана.
6. **Постобработка** — `postprocess.py` чистит текст от AI-штампов и нормализует пунктуацию.
7. **Сборка** — `report.py` собирает DOCX с GOST-форматированием через `styles.py`: A4, поля 30/15/20/20 мм, Times New Roman 14pt, межстрочный 1.5, заголовки на новой странице.

## Структура

```
src/docgen/
├── cli.py              CLI (argparse + .env loader)
├── config.py           промпты + цепочка моделей
├── llm.py              OpenRouter клиент с fallback
├── postprocess.py      avoid-ai-writing
├── report.py           оркестратор пайплайна
├── styles.py           примитивы DOCX-форматирования по ГОСТ
├── analyzer/
│   ├── scanner.py      обход файловой системы
│   └── llm_analyzer.py LLM-анализ
└── sections/
    ├── plan.py         план отчёта
    ├── abstract.py     реферат
    ├── terms.py        термины
    ├── intro.py        введение
    ├── chapter.py      главы 1-3 (универсальный)
    ├── conclusion.py   заключение
    └── references.py   список литературы
```

## Цепочка моделей

`llm.py` пробует модели по очереди, переходит к следующей при ошибке:

1. `google/gemini-2.0-flash-001` (быстрая)
2. `google/gemma-3-27b-it:free` (резерв)
3. `nvidia/nemotron-3-super-120b-a12b:free` (резерв)

Полная генерация отчёта на среднем проекте занимает 60-90 секунд.

## Ограничения

- Реферат, термины и литература генерируются LLM — могут содержать вымышленные источники. Перед сдачей проверьте список литературы вручную.
- Таблица сокращений строится по общим аббревиатурам (API, HTTP, JSON, ГОСТ, НИР...), а не извлекается из текста. При необходимости отредактируйте список в `report.py::_extract_abbreviations`.
- Рисунки добавляются как подпись + текстовое описание скриншота. Сами изображения нужно вставить вручную в Word после генерации.
- Оглавление вставлено как Word TOC field — обновите его в Word через `F9` после открытия документа.
